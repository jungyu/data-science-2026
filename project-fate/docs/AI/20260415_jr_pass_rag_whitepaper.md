# JR Pass 官方規則與合規性 RAG 諮詢系統白皮書

## 1. 摘要

本白皮書說明如何將 JR Pass 與日本區域鐵道周遊券的官方規則文件轉化為可檢索、可引用、可審計的 RAG 系統知識表徵。  
本系統的核心目標不是一般旅遊推薦，而是建立一套能以官方規則為依據、對使用者行程進行票券合規諮詢的知識型系統。

本研究重點包含：

- 如何將官方票券規則轉為可檢索的數位表徵
- 如何透過 grounding 與 citation 抑制 hallucination
- 如何處理票券規則更新、冷啟動與專有名詞對齊問題

## 2. 問題背景

JR Pass 與各地區周遊券具有高度結構化但表達形式分散的規則特徵。  
同一張票券通常會同時涉及：

- 適用區域
- 可使用天數
- 可搭乘列車類型
- 是否需要預約
- 購買或使用資格
- 票價與版本更新

這些知識雖然多來自官方網站與 FAQ，但實際呈現常是 HTML 頁面、條款說明、FAQ 與更新公告，並不是可以直接做規則判定的結構化資料。  
因此，若要做成高可信度的 RAG 系統，就必須先處理知識表徵問題，而不是只把文字塞進向量資料庫。

## 3. 知識表徵的理論難點

### 3.1 同一票券存在多層規則

JR Pass 類型知識並非單一事實，而是多層條件的組合。例如：

- 某張票只能在特定區域使用
- 某些列車可搭、某些列車不可搭
- 某些資格只適用於短期旅客
- 規則可能因版本更新而變動

這代表系統不能只做關鍵字比對，而必須將規則切成可檢索、可追溯、可對照版本的知識單位。

### 3.2 專有名詞與別名對齊

在 JR 領域中，經常出現同義詞、官方名與常用名並存的情況，例如：

- `JR Pass` / `Japan Rail Pass`
- `Kansai Area Pass` / `關西地區鐵路周遊券`
- `Tokyo` / `東京` / `東京都`

若 embedding 與 retrieval 無法正確對齊這些術語，系統就可能檢索錯誤規則片段，進而產生錯誤判斷。

### 3.3 修訂敏感性

JR 官方規則並非永久不變。票價、適用範圍、FAQ 說法與購票資格都可能隨版本更新。  
因此這是一個典型的 revision-sensitive domain。  
若系統無法辨識資料版本，就可能引用過期資訊，降低整體可信度。

## 4. 系統如何解決 hallucination

### 4.1 僅使用官方語料

第一版系統只 ingest 官方 JR Pass 與區域票券文件，包括：

- 官方規則頁
- 官方區域票券說明
- 官方 FAQ
- 官方票價與資格更新公告

這能降低非官方部落格、論壇與二手整理資料造成的錯誤引用風險。

### 4.2 Retrieval-First 架構

系統採用 retrieval-first 的回答流程：

1. 根據使用者行程與問題先檢索官方規則片段
2. 對檢索結果做 reranking
3. 通過 grounding gate 後再做合規判定
4. 最後才生成文字回答

這代表模型不能先自由推論，再回頭找證據補強；證據必須先存在，答案才能成立。

### 4.3 Grounding Gate

本系統設置一個明確的 grounding gate：

- `pass`：證據足夠，可正常回答
- `fallback`：證據部分足夠，需保守回答
- `block`：證據不足，應拒答或限制回答

當 evidence 不足時，系統不得：

- 編造規則
- 虛構引用
- 用模糊語句冒充官方結論

### 4.4 合規判定與文字生成分離

系統將「規則判定」與「自然語言生成」拆成兩層：

- 規則判定層負責整理檢索證據與資格條件
- 生成層只負責將結果轉成易讀文字

這種設計可降低模型在生成時自行加入未被證據支撐結論的風險。

## 5. 冷啟動與術語對齊問題

### 5.1 冷啟動問題

當新增票券、FAQ 更新、區域說明頁重寫時，系統可能面臨新知識尚未完整 ingest 的冷啟動問題。  
本系統的對策包括：

- 至少每 24 小時更新一次官方規則資料
- 對每個 chunk 保留 revision metadata
- 當資料可能過期時顯示 warning

### 5.2 術語對齊問題

系統在 ingestion 與 retrieval 階段都保留以下重要 metadata：

- `pass_name`
- `coverage_area`
- `rule_category`
- `revision_date`

這些欄位可協助 embedding 之外的 metadata filtering，提高對專有名詞、區域名稱與版本差異的辨識能力。

## 6. 創新性

本系統的創新點不在於單純把旅遊問答做成 RAG，而在於以下三個方向：

### 6.1 權威語料優先

系統優先追求「規則可信度」而非「語料量最大化」。  
這種設計更適合票券合規諮詢，而不是一般旅遊閒聊。

### 6.2 合規判定與生成分離

多數一般 RAG 問答系統會讓 LLM 直接根據檢索結果生成回答。  
本系統則額外設計合規判定層，使「規則理解」與「文字生成」分離。

### 6.3 Revision-Aware Retrieval

系統將修訂版本視為第一級 metadata，而不是事後補充說明。  
這讓系統在面對規則更新時，不只檢索得到答案，還能辨識答案是否可能過期。

## 7. 結論

JR Pass 官方規則與合規性 RAG 諮詢系統的核心價值，在於把官方票券知識轉換成：

- 可檢索
- 可引用
- 可解釋
- 可審計

的數位知識表徵。

這個系統不是一般的旅遊推薦器，而是一套以規則證據為中心、能降低 hallucination 並支援合規判定的 RAG 架構。  
在資料持續更新與術語高度專業化的場景下，這樣的設計比單純向量問答更適合作為高可信度知識系統。
